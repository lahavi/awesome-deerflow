# Contributing to Awesome DeerFlow

First off, thanks for taking the time to contribute! 🦌

This list is intentionally **curated, not exhaustive**. The goal is a small set of genuinely useful DeerFlow resources, not a link dump. These guidelines keep it that way.

## What we're looking for

Resources you have actually used and would recommend — for example:

- Official docs, guides, and release notes.
- Deep dives into DeerFlow 2.0's architecture (SuperAgent harness, skills, sub‑agents, sandbox, memory, InfoQuest, Claude Code integration, TUI).
- Setup, deployment, and observability walkthroughs (local‑first, Docker/Kubernetes, LangSmith/Langfuse).
- Tutorials, video tours, and community experiments that show real workflows.
- Integration examples (model providers, MCP servers, IM channels).

## What we'd rather not have

- Link spam, SEO pages, or paywalled content with no free path.
- Low‑signal list‑of‑links posts with no original analysis.
- Outdated v1‑only content that no longer applies to 2.0.
- Duplicates of existing entries.

## How to add or update an entry

1. **One entry per PR** whenever possible — it keeps review fast and the history clean.
2. Each entry should have:
   - A **bold title** (the resource name).
   - A **one‑line description** of what it is.
   - 1–2 sentences on **why it's useful in a DeerFlow context**.
   - The **link** on its own line.
3. Place it in the most specific existing section. Open an issue first if you think a new section is warranted.
4. Match the surrounding tone and formatting (em‑dashes, `---` separators, trailing two‑space line breaks inside entries).

Example entry shape:

```markdown
- **Resource Name – Publisher**  
  One sentence on what it covers.  
  A sentence on why it matters for DeerFlow.  
  https://example.com/resource
```

## Before you open a PR

- Check for broken links and deprecated content.
- Verify the resource reflects **DeerFlow 2.0** (the ground‑up rewrite), not just v1.
- Make sure your entry isn't a duplicate.

## Opening issues

Feel free to open an issue for:

- Broken links or deprecated content.
- Proposed new sections.
- Suggested improvements to existing descriptions.

## Style notes

- Prefer **fewer, better links** over long lists.
- Follow the [Awesome Manifesto](https://github.com/sindresorhus/awesome/blob/main/awesome.md) principles for quality and clarity.
- Keep descriptions concise and skimmable.

Thanks again for helping make this list genuinely awesome!
